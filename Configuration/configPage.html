Arcfin Sync

Defaults, locks and devices for everyone who uses Arcfin on this server.

How it works

  • Arcfin keeps each user's settings in step across their iPhone, iPad, Mac and Apple TV.
  • On Settings, give any setting a default (used until someone picks their own) or lock it (everyone gets your value and can't change it).
  • On Users & Devices, see every device signed in with Arcfin, rename or forget one, and give a single user their own defaults and locks.
  • On Features, choose who can use Pick Together (swipe through titles until everyone agrees) and watch parties (join with a code, now or at a time the host picks, then watch together), turn the recommendation rows on Home on or off, and let people hide titles from Continue Watching and Next Up.
  • On Seerr & TMDB, add their keys once for everyone. They stay on this server, encrypted, and Arcfin uses Seerr through it as each person, with their own Seerr limits. Requests made while Seerr is down are sent when it's back.
  • On Security, turn on signed commands, then clear a profile's PIN or lock and unlock a profile on all its devices. PINs never leave the devices; Arcfin only carries out commands signed with this server's key.
  • On Watch Time, give anyone daily minutes and a bedtime. The server counts time from every app and stops playback when it's up.
  • On Household, set up shared accounts, and show announcements or planned maintenance in Arcfin.
  • On Downloads, cap how many movies, episodes and songs each person can keep downloaded across their devices.
  • Everything is off until you turn it on.
  • Changes reach each device the next time Arcfin syncs: when it opens, comes to the front, or a setting changes.

Encryption

Signed Commands

Turns on the signing key, PIN clearing, locks, wiping devices and the rules below. Until it's on, no key is made and devices don't check in.

PINs never leave people's devices. Instead, this server can send signed commands that Arcfin carries out: clear a profile's PIN, lock a profile on all its devices, or unlock it. Each device checks every command's signature against this server's key, so only this server can send them.

How a device learns the key: over HTTPS it trusts the key the first time, because the system has already checked the server's certificate. Over plain HTTP it can't be sure who answered, so Arcfin shows the key's fingerprint in Settings › Server and waits until someone confirms it matches the one below. A new key you make later is signed by the old one, so devices move to it on their own; any other change of key needs the fingerprint checked again.

Signing Key

Replace the key completely

For a key you think has leaked. Makes an entirely new key that the old one doesn't vouch for, and deletes the record of past keys, so the old key can't move any device anywhere. Locks and other commands stay in force. Every device has to trust the new key again: over HTTPS that happens by itself, and over plain HTTP someone has to check the new fingerprint in Settings › Server on that device. Until then, those devices ignore your commands.

Use your own key

An EC P-256 private key in PEM, e.g. from openssl ecparam -name prime256v1 -genkey -noout | openssl pkcs8 -topk8 -nocrypt. It's stored encrypted and can't be read back. A key of your own can't be rotated automatically, so using one turns rotation off: for the strongest setup, let the plugin make and rotate its keys.

Trusted Devices

A new device shows a code and waits; the person approves it on one of their trusted iPhones or iPads, or you approve it under Users & Devices. Devices already signed in when you turn this on are trusted, and so is someone's first device.

For one person

PIN Rules

The longest a PIN can be is 8 digits. With a number of tries set, a profile locks on that device after that many wrong PINs, until you unlock it under Users & Devices.

Require HTTPS Away from Home

Arcfin won't use plain HTTP unless the address is on the local network (like 192.168.x.x or a .local name). This rule is signed, so nothing on the network can turn it off.

Devices on Plain HTTP

A device that reaches this server over plain HTTP can't be sure who answered, so it asks someone to check the key's fingerprint before it carries out your commands. It checks by itself where it can: if the app also has this server's HTTPS address saved, it fetches the key from there and trusts it when they match. Anyone can compare with the fingerprint shown in Settings › Server on a device that already trusts the key.

For households where no one will check. This setting reaches devices over plain HTTP too, so on a network you don't trust it could be faked: keep it for your home network.

Automatic Rotation

Makes a new key on a schedule, each signed by the last, so devices move over by themselves. A device that falls behind can't use an old key for long (see the next card). The key is kept on this server, so rotation doesn't protect against someone who already has the server; what it does is put a limit on how long any one key is trusted. It only works with a key the plugin made: using your own key turns it off.

Devices That Fall Behind

Every Arcfin device tells the server which key it holds when it syncs. One that hasn't picked up the current key for this long is signed out, so it has to sign in again; or signed out and locked, so Arcfin won't open on it until you unlock it below. Only Arcfin devices that have checked in are counted, and the count starts from when you turn this on.

For one person

Older Arcfin versions

Arcfin from before 0.5.0 build 3's security features can't check in, follow key changes or show a lock. Arcfin Sync tells them apart by whether they check in, not by version number, since every build of 0.5.0 reports the same version. Someone you lock is signed out of an older Arcfin straight away either way; to keep them off the server in every app, disable their account when you lock them.

Each device's key status, and older Arcfin versions, are under Users & Devices, with the person they belong to.

Shared Accounts

Pick an account used by several people, for example the one on the living-room TV, and tick who watches on it. When something plays on a shared account, Arcfin there asks who's watching, and their own progress and watched status follow along.

Announcements

A banner in Arcfin, for everyone or chosen people, from and until the times you set. Nothing shows until you add one.

Planned Maintenance

When the server will be down. Arcfin warns people ahead of time, then shows when the server will be back instead of a connection error. Windows that have ended are removed.
